# Learning — sdgh-jira-access

## 样例 5 — 2026-08-20

**测试场景**：公司 Windows 电脑无法打开系统凭据窗口，或执行权限策略要求用户交互。

**发现的问题**：
- 原流程只要系统窗口启动失败就会中断。
- Windows 加密也依赖 PowerShell，即使改用终端输入，PowerShell 被禁用时仍无法完成配置。
- 用户主动取消和系统窗口故障需要不同处理。

**调整方案**：
- 系统窗口故障时自动切换到终端隐藏输入，用户主动取消时停止。
- Windows 改为 Python 直接调用系统 DPAPI 加密，不把 PowerShell 作为安全保存凭据的前提。

**验证结果**：
- 待完成自动化测试、Windows CI 和远端安装验证。

## 样例 4 — 2026-08-20

**测试场景**：将 Skill 分享给主要使用 Windows 的公司同事。

**发现的问题**：
- 原配置流程只支持 macOS 钥匙串和系统弹窗。
- 文档固定使用 `python3`，Windows 常见的 `py -3` 或 `python` 无法按同一文案执行。

**调整方案**：
- Windows 增加系统凭据窗口和当前用户 DPAPI 加密存储，macOS 保留钥匙串。
- 安装和运行时由 AI 自动探测 Python 3 命令，不让用户填写解释器路径。

**验证结果**：
- 9 个自动化测试和 Skill 结构校验通过，Windows 分支已覆盖配置目录、DPAPI 解密调用和配置文件不保存明文密码。
- macOS 本人身份回读成功，GitHub 远端全新安装和远端测试通过。

## 样例 3 — 2026-08-20

**测试场景**：公司同事只发送一句安装请求，不再额外提供 Jira 地址。

**发现的问题**：
- 原安装文案仍要求每位同事填写相同的公司 Jira 地址，增加了无意义的输入步骤和拼写风险。

**调整方案**：
- 将公司 Jira 基础地址内置为 `setup` 默认值，安装流程只询问本人账号和隐藏密码。

**验证结果**：
- 默认参数测试、本人身份查询、6 个自动化测试和 GitHub 远端安装均已通过；远端安装包的 `setup --help` 已确认显示公司默认地址。

## 样例 2 — 2026-08-20

**测试场景**：将已经安装和公开分发的 Jira Skill 重命名为 `sdgh-jira-access`。

**发现的问题**：
- Skill 名称同时存在于源目录、frontmatter、调用方、Codex 软链接、配置目录、钥匙串服务名和 GitHub 地址，单点改名会产生断链。

**调整方案**：
- 将名称迁移作为一次完整安装迁移处理，逐项更新并验证，不保留两个活动入口。

**验证结果**：
- 新名称下的 Skill 结构校验、5 个自动化测试、本人身份查询和 GitHub 远端安装均已通过；旧名称只保留在版本演进和环境变更历史中，不再作为活动入口。

## 样例 1 — 2026-08-20

**测试场景**：安装 Skill 后直接查询本人负责的 Jira，并预检一张新工单。

**发现的问题**：
- Jira 的通用需求类型存在模块、处理人和预计上线日期三个无默认值的必填字段。
- 读取详情时需要同时保留标准字段、自定义字段、评论和真实链接，才能替代页面查看。

**调整方案**：
- 创建前固定先读取实时元数据，再用 `prepare-create` 列出缺失必填项。
- 查询和详情结果返回简化后的结构化字段及真实 Jira URL。
- 所有写命令保留 `--confirm` 机器保护，缺少该参数时不发送写请求。

**验证结果**：
- 本人身份验证成功，可查询本人负责工单和详情。
- 实时识别出模块、处理人、预计上线日期三个缺失必填项。
- 不带 `--confirm` 的修改命令被本地拦截，未写入 Jira。
